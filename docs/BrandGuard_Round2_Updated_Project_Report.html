1. Executive Summary & Round 2 Build Status

Organisations publish through many hands at once—employees, external agencies, freelancers, and AI writing assistants—leading to outdated facts, unsupported promotional guarantees, misused terminology, off-palette visuals, and inaccessible design.

In Round 2 (The Build), Team Nexus has transformed the Round 1 proposal into a fully functional, end-to-end web application built with Python 3.12, FastAPI, SQLite3, and an interactive Single-Page Application (SPA) frontend. Every step of our 9-step governance sequence works end-to-end without requiring a walkthrough or login barrier.

Zero-Friction Judge Evaluation: Opening the application link in an incognito window loads directly into an active workspace pre-seeded with the ABC SmartFlow Global Brand Kit v3 (14 verified rules), a 1-Click Role Switcher (Creator, Reviewer, Manager, Admin), and 3 live submissions demonstrating active review (including the exact BG-001 finding from Round 1), Step 5 Amber Escalation, and Step 8 Publish-Ready Compliance Records.

3. Technology Stack & Implementation Architecture

  • Backend API: Python 3.12 with FastAPI, Pydantic v2, and Uvicorn, organized into modular routers (auth_routes.py, brand_kit.py, submissions.py, insights.py) and engine modules (redactor.py, deterministic.py, ai_judge.py, validator.py, diff_utils.py, orchestrator.py).
  • Database Layer: SQLite3 with 9 normalized tables and transactional foreign-key enforcement.
  • Deterministic Checks: Regular-expression rule tables, ISO date expiry checks, WCAG 2.1 relative luminance and contrast ratio formula, perceptual RGB color distance ($\Delta E$), and Flesch-Kincaid readability grading.
  • AI & Offline Fallback: Supports Anthropic Claude API (claude-3-5-haiku-latest) on redacted text with an automatic deterministic heuristic fallback for tone (G-01) and nuanced claims (C-02) when running offline or without API keys.
  • Security & Privacy: PBKDF2-HMAC-SHA256 password hashing (100,000 iterations), HMAC-SHA256 signed bearer tokens, server-side role verification, and local redaction of [[confidential]] spans.

4. Explanation of Changes Made from the Original Round 1 Proposal

  1. Added Instant Judge Role-Switcher & Pre-Seeded Incognito Workspace: To ensure judges opening the link in an incognito browser are never blocked by a login screen or empty dashboard, we added a 1-click Role Switcher in the top bar (which dynamically issues real HMAC-signed tokens for Creator, Reviewer, Manager, and Admin) alongside formal PBKDF2 login.
  2. Added Client-Side HTML5 Canvas Dominant Color Extraction: For visual palette checking on uploaded images, we implemented an HTML5 Canvas pixel sampler in the frontend paired with RGB color-distance math in the backend so image palette compliance runs instantaneously without external vision API latency.
